# Do reasoning models collapse on hard puzzles?

This is the first version of the experiment. It stopped at 285/750 confirmation responses; the [complete run](../complete-run/) re-analyses the saved responses and adds a move-level analysis.

Question: Does Qwen3 lose exact puzzle-solving accuracy as solution length grows, and can asking for a program restore it?

Sources: [Shojaee et al., 2025](https://arxiv.org/abs/2506.06941), [Lawsen, 2025, v2 rebuttal](https://arxiv.org/abs/2506.09250). The original reports three accuracy regimes and declining reasoning length near collapse. The rebuttal distinguishes enumeration from algorithms, acknowledges its earlier token calculation error, and flags impossible river-crossing instances. We will use only constructively solvable puzzles, not that river-crossing task.

## Before pilot
Setup: NVIDIA L4, vLLM, public Hugging Face Qwen/Qwen3-4B pilot then Qwen/Qwen3-8B confirmation. No private data or paid APIs. Programmatically generated Hanoi n=3..10 and checker jumping n=2..5. Random labels and source/target permutations give paired instances; these are isomorphic variants, not independent mathematical problems. A deterministic state simulator checks every move and final goal. Programs are executed with restricted builtins in a resource-limited subprocess and checked by the same simulator.

Pilot: 2 instances per selected level (Hanoi 3,5,7,9,10; checkers 2,4), both thinking modes, plus Hanoi program at 9,10. Pilot informs exact threshold/medium levels, not confirmatory estimates.

Confirmation: 25 fresh instances per level per mode, paired prompts, generation seeds fixed; programs at Hanoi 8..10 in both modes. Same 16,384 output-token ceiling for all arms, with a 20,480 context window. Compact move encoding keeps the canonical n=10 Hanoi answer far below the ceiling; measure actual tokenizer length before confirmation. Temperature 0.6, top_p 0.95, top_k 20, one sample per item/mode. All generated token counts, termination reasons, raw text, timings and verifier reasons saved incrementally. Length-limited outputs count as task failures but are separately tabulated; causal claims about non-truncated collapse require <=5% truncation in relevant cells. If budget cannot support full completion, report incomplete cells, do not silently reduce sample sizes.

## Fixed decision framework
H1: thinking improves medium complexity accuracy. H2: both modes approach zero above a pilot-selected threshold. H3: thinking token use peaks then falls at high complexity. H4: executable programs improve high-complexity Hanoi accuracy. Exact pilot-derived levels and practical margins will be committed here BEFORE confirmation. PROVEN requires the pre-specified 95% confidence bound to clear the margin; DISPROVEN requires the opposite bound to exclude the claimed margin; otherwise INCONCLUSIVE. Report each hypothesis separately and an overall qualified verdict. Percentile bootstrap 10,000 paired resamples for differences/means, per-level bootstrap accuracy intervals plus Wilson intervals to expose uncertainty at 0/25 or 25/25. No changing hypotheses after seeing confirmation.

Hard budget: 6 CU including setup/pilot; stop before account balance falls 6 CU below initial 127.05 (account changes can include other users, so use named session rate and elapsed time conservatively too). Initial floor 103 CU, must recheck before every creation. One named Colab session only (puzzles-l4). Detached remote jobs, per-batch checkpointing, frequent local copies. Session stopped on completion/failure.

Timing: estimated 115 minutes (setup 20, GPU run 65, analysis 10, writeup 20); actual, GPU and CU pending. See results/timing.json.

### Hardware choice before confirmation
The 4B pilot uses BF16 and eager execution. For confirmation use the official [Qwen/Qwen3-8B-AWQ](https://huggingface.co/Qwen/Qwen3-8B-AWQ) release, 4-bit AWQ weights with BF16 activations/KV cache, and vLLM CUDA graphs. This preserves KV-cache room for batching long outputs within the L4/6-CU budget. All confirmation modes share the same quantized weights; findings apply to this release, not automatically to BF16 8B. This setup choice is made while the pilot is running and before any 8B confirmation outputs exist. Confirmation uses an independent fixed RNG seed per item (118 + 1000*cell_index + item_index), unlike the tiny exploratory pilot's shared cell seed. Qwen's recommended thinking sampling is held fixed across modes, rather than separately optimizing OFF.

Pilot operations note: after the first eight saved responses, the runner was changed from sequential two-request cells to a streaming queue, keeping the GPU occupied and checkpointing each finished answer. The in-flight cell was interrupted, completed outputs retained, and unfinished item IDs resubmitted with their original pilot seeds. This is an execution change before confirmation; batch-dependent floating-point differences are possible. The old runner is retained as scripts/run_gpu_batched.py. Program requests are scheduled first, then move cells; cell indices and item seeds remain stable. This guards against losing the representation comparison to a late budget stop.
The first streaming restart failed because the interrupted vLLM child retained GPU memory. Its exact PID was terminated (only this experiment's engine), the failure log saved as figures/stream_restart_failure.txt, then the pilot resumed. No additional model outputs were obtained by that failed restart.

## Frozen confirmation hypotheses (before any 8B inference)

**Pilot deviation and evidence:** Stop the exploratory 4B pilot after 18/36 planned completed responses to reserve the 6-CU budget for confirmation. Unfinished requests are NOT scored as incorrect. Completed Hanoi move-list results: n=3 OFF 0/2, ON 2/2; n=5 OFF 0/2, ON 1/2. All eight programs at n=9,10 passed. Two checker OFF n=2 answers failed. Long pending move-list requests had not completed and provide no accuracy or token-length estimates. This is a small and intentionally noisy pilot, not evidence that the high-level failure threshold is already known.

- **H1:** On Hanoi n=4,5,6, thinking ON improves exact accuracy over OFF by **more than 10 percentage points**, pooled equally over levels, 75 paired instances. Medium levels bracket the observed n=5 advantage of 50 points. Ten points means ten fewer broken workflows per hundred requests; smaller gains are not the target of this budgeted test.
- **H2:** Both move-list modes have **less than 10% exact accuracy at Hanoi n>=7**, pooled separately per mode (100 responses each). Threshold 7 is derived, not guessed: pilot ON n=5 success was 1/2 over 31 moves. A deliberately crude independent-move heuristic gives p=(1/2)^(1/31)=0.97789, predicting p^127=5.85% at n=7, the first integer level below 10%. This extrapolation to the larger, quantized 8B model is risky and is precisely what confirmation tests. Lawsen explicitly questions such error-accumulation arguments; this is a prediction heuristic, not a causal model or a proof of inability. PROVEN requires both 95% Wilson upper bounds below 10% AND <=5% cap hits in every relevant level/mode cell. Report the n=3 baseline too: an already-weak OFF baseline cannot establish a fall from prior competence.
- **H3:** Hanoi thinking tokens rise by **at least 20% from n=3 to n=5**, then fall by **at least 20% from n=5 to n=10**. Both independent-bootstrap ratio intervals must clear 1.2 and 0.8 respectively, with <=5% truncation at each compared level. n=5 is the highest completed pilot move-list level and had 3.49x the n=3 mean thinking tokens. The late decline is paper-motivated, not observed in this shortened pilot. A 20% decrease would materially contradict allocating more inference compute as problems get longer. Other observed peaks will be descriptive only, not a replacement hypothesis.
- **H4:** At Hanoi n=8,9,10, requesting an executable program improves verified accuracy by **more than 50 percentage points** over requesting all moves. Pool equally over levels and thinking modes, 150 paired outputs per representation. The pilot's 8/8 executable successes plus the rebuttal motivate a large effect; recovering more than half of requests is a meaningful engineering intervention. This tests model-plus-interpreter, not unaided mental execution.

Confirmation uses 25 fresh items per cell, 24 move cells + 6 program cells = **750 responses**. Synthetic instance seeds are 918000 + 1000*(family is checkers) + 100*n + item, distinct from pilot base 118000. Per-item generation seeds are independent and fixed (118 + 1000*original cell index + item). All cells retain the same 16,384-token ceiling and decoding recipe. The compact ten-disk answer is 4,094 tokens. This fits the required answer but cannot guarantee that a model's thinking terminates; censored conclusions are explicitly gated.

Statistical rules: 10,000 bootstrap replicates, 95% intervals; paired, stratified resampling of item differences within fixed level/mode strata for H1/H4; independent item resampling for H3 ratios. Per-level bootstrap accuracy intervals saved as requested, with Wilson intervals displayed because bootstrap is degenerate at 0/25 or 25/25. H2 uses Wilson bounds. PROVEN requires all relevant bounds to clear the practical margin; DISPROVEN requires a bound to exclude the claimed margin in the opposite direction; otherwise INCONCLUSIVE. Truncation gates prevent declaring an uncensored effect. Report each hypothesis independently at nominal 95%; no familywise claim. The combined three-regime pattern is PROVEN only if H1-H3 all pass, DISPROVEN if one is disproven, otherwise INCONCLUSIVE. H4 is separate. Missing planned cells make affected claims INCONCLUSIVE.

With 75 pairs H1 targets the pilot's very large effect, not tiny improvements. H2 has 100 observations per mode: 0/100 still has a Wilson upper bound of 3.7%, comfortably below 10%, whereas 0/25 alone would not establish a <10% rate. H4 has 150 pairs to test a very large representation effect. H3 may remain uncertain under high variance or censoring. No hypothesis will be reworded after confirmation.
